# Navigation Arena

This regular authored game project places a kinematic enemy and its patrol destination on opposite sides of a solid central box. Its optional `Config/EnemyNav.knav` is a planar mesh of eight rectangles with a central hole. The enemy uses existing NavMesh A*/funnel routing and the existing crowd/motor adapters rather than direct steering. The primary player's sight range is deliberately small in this sample so the patrol is observable.

Format: `kairo-enemy-nav 1`, `height Y`, then `rect X0 Z0 X1 Z1` for each center-walkable rectangle (maximum 256). Adjacent rectangles must share whole matching edges for connectivity. Authors must inset walkable space for capsule clearance and exclude physical obstacles. A missing nav file preserves the previous direct-steering behaviour. With a nav file, unavailable paths stop planar movement rather than falling back through obstacles. Goal refresh is rate-limited to 12 fixed decision ticks, with the existing crowd adapter retaining its independent stuck-replan policy. Crowd avoidance is limited to path-following registered NPCs; the character motor resolves solid contacts. Static authored geometry only; automatic navmesh baking, multi-level meshes, dynamic door carving, and crowd quality are not certified.

Run `build/game-clang/Runtime/KairoPlayer/KairoPlayer Samples/NavigationArena/Project.kproject` after building the normal game profile. The full-workspace CTest `KairoPlayerEnemyNavigationBridgeTests` checks that the NPC detours around the solid central blocker and reaches the opposite patrol point. Portable tests verify the parser and replan budget, not the physical detour.
