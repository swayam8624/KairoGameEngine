# Event Arena

Regular authored project with a beacon and a proximity trigger at spawn. Four declarative event rules show a start marker, reveal a second marker on trigger entry, hide the start marker when the beacon is collected, and reveal the completion marker when the objective is complete. No custom runtime executable or native plugin is required.

`Config/Events.kevent` starts with `kairo-events 1`, then `on RULE_ID EVENT SOURCE_ID THRESHOLD once|repeat show|hide TARGET_ENTITY_ID`. Events are `begin` and `complete` (source 0), `collected` (collectible entity ID), `trigger` (trigger rule ID), `defeated` (combat target ID). Rules count matching events and act on the threshold occurrence; repeating rules reset the counter. Matching actions execute in ascending rule ID order. The generic Player dispatches start before its first render, then defeats, triggers, collections and completion in the gameplay frame. Actions affect only opted-in `kairo.event-visual` root visual leaves, with no other ownership tags or physics/gameplay components. Events do not recursively emit events. Rules are session-local and currently reject `--progress-file` rather than silently restore incompatible state. This feature supplements the existing compiled visual logic; it is not a general-purpose scripting language.

Build the normal game profile, then run `build/game-clang/Runtime/KairoPlayer/KairoPlayer Samples/EventArena/Project.kproject`. Native acceptance: `python3 Samples/EventArena/run_native_acceptance.py build/game-clang/Runtime/KairoPlayer/KairoPlayer Samples/EventArena metal`. The native gate covers the four-rule chain and malformed bindings, not an interactive defeat journey.
