# Key Gate Arena

A normal authored Kairo project demonstrates a gate that stays closed until the player collects a key. The event `on 1 collected 50 1 once door-open 40` commands the registered door to hold open, and its existing fixed-step adapter moves the collider and mesh together. The door file accepts an optional initial mode (`auto`, `open`, `locked`); old records remain automatic. Other event actions are `door-lock` (close when the primary player is outside the authored activation radius, then stay closed) and `door-auto` (resume proximity-driven operation). A lock command does not close an already-open gate while the primary player is near. This is a conservative primary-player policy, not general crush prevention or continuous obstruction detection. Door/event state is session-local; event projects reject the progress-file option.

After building the game profile, run `build/game-clang/Runtime/KairoPlayer/KairoPlayer Samples/KeyGateArena/Project.kproject`. Native tests include the direct physics adapter round trip and a generic Player smoke that places the key at spawn in a temporary copy to verify actual event dispatch. The ordinary authored project retains the off-spawn key.
