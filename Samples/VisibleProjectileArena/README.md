# Visible Projectile Arena

A normal authored game project derived from Projectile Arena. Press F to fire along the last movement direction. Eight pre-authored projectile marker entities are reused in stable ID order; active slots follow the authoritative fixed-step flight positions. Expiry, impact, cancellation or respawn hides unused slots. The marker roots start disabled, carry `kairo.projectile-marker`, have a regular mesh and no physics or competing gameplay components. The visual pool does not change damage, range or collision behaviour. A flight beyond the authored marker capacity remains simulated but invisible.

Optional imported character animation: put `kairo.combat-animated` on one active imported scene-instance leaf directly parented to the primary player. It must expose distinct `Idle` and `Attack` clips. The render bridge resolves these at native startup, loops Idle and restarts the clamped Attack clip on an accepted attack; after a 0.35-second presentation window it returns to Idle. This is a hard clip switch, not crossfading or movement-aware locomotion blending. The provided primitive-mesh arena demonstrates projectile markers, not a skinned attack asset. Menu pause freezes both the flight and presentation clocks. No impact particles, trails, audio or procedural projectile GPU allocations are introduced.

Build the game profile and run `build/game-clang/Runtime/KairoPlayer/KairoPlayer Samples/VisibleProjectileArena/Project.kproject`. `KairoPlayerCombatPresentationBridgeTests` checks actual scene marker activation, position, impact, cancellation and reuse against the physics-backed combat adapter. It is a headless full-workspace test, not a GPU capture. The portable policy test checks bounded slot selection and launch-window timing independently.
