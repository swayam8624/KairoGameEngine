# Local authoritative networking lab

Build and run from the integration root (Linux/macOS):

    c++ -std=c++23 -Wall -Wextra -Werror Samples/NetworkLab/NetworkLab.cpp -o /tmp/kairo-net
    python3 Samples/NetworkLab/run_pair.py /tmp/kairo-net

Windows uses Winsock and needs ws2_32 (CMake target links it). The Linux
GCC/Clang evidence does not verify Windows or macOS. The server chooses an
ephemeral IPv4 loopback port and accepts one client, exchanges ten frames,
and exits. The client sends unit-axis input, not positions. Server validates
sequence numbers, applies movement, and sends authoritative snapshots.

Read RuntimeNetworkProtocol.hpp before RuntimeLoopbackTcp.hpp, then the
protocol tests and this sample. The versioned 20-byte big-endian frame is
independent of sockets. TCP partial reads/writes are handled explicitly.
This is a narrow local one-client prototype, not a distributed game,
authentication, encryption, NAT traversal or loss/reconciliation solution.


The client also predicts its movement locally and reconciles the returned server snapshot. The separate RuntimeNetworkPredictionTests.cpp tests delayed, dropped and reordered snapshots, corrections and bounded journal backpressure; this does not claim UDP reliability.

## Local matchmaking

Run python3 Samples/NetworkLab/run_matchmaking.py PATH_TO_KairoNetworkLab scripts/kairo_matchmaking.py. The harness advertises the server's actual loopback port, discovers it, reserves one seat, runs the native client, releases the seat and closes the advertisement. The directory CLI also exposes create/list/join/leave/close, with atomic SQLite transactions and expiry. Shared database is trusted local storage; tokens are not remote authentication, and the TCP server does not enforce them. No WAN, ranking, lobby UI, or hosted service. The lab supports one client; larger capacities are directory tests only.

## Two-client co-op authority

KairoCoopLab server prints a loopback port. Start two KairoCoopLab client PORT processes within the five-second accept window. Both independently submit six right moves; the shared objective is to occupy both exit cells simultaneously. The authoritative server waits for one input per seat, rejects stale/future/diagonal inputs and commits both actors together, preventing contested-cell overlap and swaps. Two ordered snapshots represent one turn. The Python runner verifies all six turns on both actual clients and rejects four malformed/disconnect scenarios. Turn-based, two seats, 256 turns, per-frame 30-second deadline. No Internet access, authentication, reconnect, matchmaking admission token, lag compensation or graphical client in this PR. Shutdown aborts an in-flight socket operation without relinquishing ownership; callers must join before destruction.

## Graphical co-op client

Build KairoCoopLab and KairoCoopClient in a configured native workspace. Start the server, read its READY port, then launch two KairoCoopClient PORT --renderer metal (or vulkan) processes within the accept window. Arrow keys submit one cardinal move; Space submits a wait. White border marks your actor; each colored actor must reach its matching exit. The window stays responsive during peer wait, with at most one outstanding turn; closing interrupts blocked I/O before joining. The initial connection handshake is synchronous; it is bounded by transport timeouts and is not a matchmaking UI. The 30-second per-frame timeout still applies during play. Run run_coop_native.py SERVER CLIENT metal (or vulkan) for the two native capture gate. No native execution observed for this branch yet.

### Protected local co-op

Set both `KAIRO_COOP_SEAT0` and `KAIRO_COOP_SEAT1` in the server's environment to distinct 64-character lowercase hex tickets generated by an OS-backed random generator (e.g. Python `secrets.token_hex(32)`). Pass only the corresponding `KAIRO_COOP_TICKET` to each CLI or graphical client. Do not place real tickets in source control, command arguments, or shared logs. Seat numbers now follow the server's ticket mapping even if seat 1 connects first. Invalid, malformed, partial and reused tickets cannot reserve the other seat. Admission has a two-second per-peer handshake deadline and an eight-attempt cap; a hostile local process can still deny service. If neither server variable is set, the legacy open loopback lab is preserved; setting only one is an error. This is a local bearer-ticket teaching feature, not encrypted WAN authentication or automatic SQLite directory enforcement.

The portable `run_coop.py` gate covers protected and open modes with real processes; the native `run_coop_native.py` gate requires the correct protected seat on each graphical client and a capture change. Native evidence is pending until those CI jobs complete.
