# Kairo Studio production release contract

This is the bounded first public engine release scope, not a claim of parity with every feature of a commercial engine. Do not label the release 100% until each gate has actual integrated evidence. Do not require the owner to iterate manually on incomplete native builds; the final owner-run Mac check follows the release candidate gate.

| Gate | Required acceptance | Present evidence / outstanding work |
| --- | --- | --- |
| Project hub | Open/create 2D, 3D and sample projects; recent projects, safe paths, missing-project recovery, engine/version information, no shell command construction from names | Existing project session, recipe compiler and lifecycle tools; dedicated startup hub and template workflow remain |
| Editor interaction | Selection never frames or moves camera; F frames explicitly; Q/W/E/R tools outside RMB; orbit/pan/dolly/free-look on mouse and trackpad; no clicks on toolbar treated as scene picks; undoable local/world transforms, parent hierarchy, cancel and redo | Native shell changes for gesture ownership and explicit framing; local geometry test; full mouse interaction, transformed children, retained selection and Retina picking acceptance pending |

## Evidence rules

Keep actual commands, candidate commit and workspace lock, completed results, logs and captured frames. A portable test cannot certify GPU interaction. A source edit cannot certify native behavior. Missing acceptance is not a percentage. Distinguish static checks, local executed tests, CI and owner device tests. Preserve unmerged work and build caches until verified promotion.

## Pass 9: geometric selection contours

Static selected meshes now use camera-dependent contours from cached welded triangle adjacency, respecting submitted draw IDs, parent/model transforms, orthographic and perspective views and mirrored winding. Explicit save validates finite strictly increasing times, unit rotation quaternions, target node identity and bounded counts. The shared Editor/Player glTF import boundary appends the project-owned Animations/<asset-id>.kanim clip after imported clips, retaining imported indices. Save updates live animation bindings without restarting the editor. Runtime default remains clip zero; gameplay can select the appended index. Authored clip edits are asset-wide, require rest-TRS nodes, and are not scene undo commands. Simultaneous file writers are not supported; a changed source key is rejected on reload, not automatically retargeted. Multiple authored clips, unsaved draft preview, general scene-entity animation and state-machine editing remain outstanding.

## Pass 14: live logic breakpoint and instruction control

The built-in Player's opt-in instruction observer now supports break on first instruction or one source-bound breakpoint selected from a previous recorded trace (document UUID, source SHA-256, PC). The Editor writes session-specific configuration before launching Play and inspects an atomic paused-state snapshot with pre-instruction registers. Continue, single-instruction step (across branches and dispatches), and detach use unique monotonically increasing stop tokens and bounded command files. The Player thread waits inside the pre-instruction observer, not by replaying or restarting bytecode, so the VM stack and instruction budget survive the stop; the game window may be unresponsive while paused.
